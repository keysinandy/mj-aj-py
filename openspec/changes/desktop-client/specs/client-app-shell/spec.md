# Spec Delta

## Purpose

定义桌面客户端壳与本地服务的生命周期行为、平台连接设置与模型管理,保证客户端开箱即用且令牌等敏感配置不外泄。

## ADDED Requirements

### Requirement: 服务生命周期与连接状态
客户端启动时SHALL自动拉起本地服务进程并建立连接;界面SHALL持续显示连接状态(连接中 / 已连接 / 断开)。服务进程意外退出时,客户端SHALL自动重启服务并恢复连接,期间不丢失已持久化的数据;用户主动停止某个对弈会话MUST NOT导致应用或服务退出。

#### Scenario: 启动即连接
- **WHEN** 用户启动客户端
- **THEN** 服务进程被拉起,界面在数秒内显示"已连接"

#### Scenario: 服务崩溃自愈
- **WHEN** 服务进程在空闲期被强制终止
- **THEN** 客户端重启服务并恢复"已连接",此前保存的设置与种子库仍可用

#### Scenario: 停止会话不停应用
- **WHEN** 用户在任一对战模式中点击"停止"
- **THEN** 仅该对弈会话终止,客户端与本地服务保持可用

### Requirement: 平台连接设置
客户端SHALL提供设置界面,可配置服务器地址、锦标赛令牌、匹配令牌与测试房令牌(多枚),并持久化保存;保存后无须重启应用即可用于下一次会话。令牌SHALL只落在本机 gitignored 配置路径,不进入版本库与分发制品。鉴权失败(401/403)SHALL呈现可读错误并区分令牌类型不匹配与权限不足。

#### Scenario: 设置持久化
- **WHEN** 用户填写服务器地址与令牌后保存并重启客户端
- **THEN** 设置仍然生效,无须重新填写

#### Scenario: 令牌被拒的可读错误
- **WHEN** 用户用测试房令牌启动匹配房会话且服务端返回 403
- **THEN** 界面展示该令牌不可用于此模式的明确错误,会话不进入对弈循环

### Requirement: 模型管理
客户端SHALL支持导入 ONNX 模型文件作为 policy / policy-v3 策略的推理模型,导入时校验元数据(输入契约:观测平面数等),非法或契约不符的模型SHALL被拒绝且不影响当前已选模型;切换模型后对后续新会话生效。客户端运行时分发制品MUST NOT依赖 torch。

#### Scenario: 导入合法模型
- **WHEN** 用户导入与本客户端动作空间(109 维)及观测契约匹配的 ONNX 模型
- **THEN** 模型出现在可选列表,可用于新会话

#### Scenario: 拒绝损坏模型
- **WHEN** 用户导入损坏或契约不符的 ONNX 文件
- **THEN** 导入被拒绝并提示原因,当前模型选择不变

#### Scenario: 模型切换生效边界
- **WHEN** 会话进行中用户切换默认模型
- **THEN** 当前会话继续使用原模型,之后启动的新会话使用新模型
