# Spec Delta

## Purpose

定义统一回放查看器的行为:浏览本地与线上对局记录、时间线步进与进度条拖动、按记录来源区分的信息完备度视角,以及与既有重放对账工具的一致性约束。

## ADDED Requirements

### Requirement: 记录浏览
客户端SHALL列出可回放的记录来源:本地批次对局(按批次/单局)与线上对局日志(按日期/会话/gid),并支持打开任意一条进入回放;记录索引SHALL与磁盘上的既有记录目录兼容,不迁移、不改名既有文件。

#### Scenario: 打开线上对局
- **WHEN** 用户在记录浏览器中按 gid 找到一场线上对局并打开
- **THEN** 回放查看器加载该记录并显示局数、座位与终局信息

#### Scenario: 打开本地批次单局
- **WHEN** 用户展开某本地批次并选择其中一局
- **THEN** 回放查看器以全知模式加载该局

### Requirement: 步进与进度条
回放SHALL支持逐步前进与逐步后退,以及进度条拖动定位到任意步;每一步SHALL展示该时刻的手牌、四家牌河、四家副露、剩余墙数与轮次;步进与拖动的响应SHALL在人类可感知的即时范围内(预计算帧或等效机制)。

#### Scenario: 前进一步
- **WHEN** 用户点击"下一步"
- **THEN** 牌面状态推进一个动作/事件,时间线高亮对应条目

#### Scenario: 后退一步
- **WHEN** 用户在非起点点击"上一步"
- **THEN** 牌面状态回退到前一状态,与顺序推进到该步的结果一致

#### Scenario: 拖动定位
- **WHEN** 用户将进度条拖到中段任意位置
- **THEN** 牌面状态等于从头顺序推进到该步的状态,无中间残影

### Requirement: 信息完备度视角
本地批次记录SHALL默认以当前观察座位的玩家视角回放:观察座位手牌可见,其他三家暗手不可见;本地记录可显式切换到全知视角查看四家暗手。线上记录SHALL固定以自家视角回放:他家暗手不可见,仅展示公共信息与自家手牌。视角规则由记录来源决定,线上不可切换绕过。

#### Scenario: 本地默认玩家视角
- **WHEN** 打开本地批次对局或切换观察座位到另一家
- **THEN** 该观察座位位于牌桌底部并显示其手牌,其余三家暗手显示为隐藏占位,且不泄露牌面身份

#### Scenario: 本地全知开关
- **WHEN** 用户在本地回放显式打开全知视角
- **THEN** 四家暗手可见,并仍可切换观察座位改变牌桌相对方向

#### Scenario: 线上自家视角
- **WHEN** 回放线上对局记录
- **THEN** 他家暗手区域显示为未知,任何操作都不能显示其内容

### Requirement: 牌面图形与可读性
牌桌SHALL使用本地打包的 [`mahjong_graphic`](https://github.com/lietxia/mahjong_graphic) SVG 资源渲染可见手牌、牌河、副露和宝牌;牌的身份MUST NOT仅依赖小号文字标签表达。资源加载不得依赖运行时网络,牌图在牌河与副露的紧凑尺寸下仍应保持清晰;暗手未知占位可继续使用牌背图形与张数提示。

#### Scenario: 牌河和副露使用图形牌面
- **WHEN** 回放步骤包含公开弃牌或吃碰杠
- **THEN** 对应区域展示本地麻将牌图形,不展示作为牌面身份的 `1万`/`东` 等小号文字

#### Scenario: 无网络仍可显示牌面
- **WHEN** 客户端在无法访问外部网络的环境打开回放
- **THEN** 牌河、副露、手牌和宝牌仍从客户端打包资源正常显示

### Requirement: 牌桌布局可见性与副露方向
牌桌SHALL在本地全知视角完整渲染四家手牌,左右座位的手牌不得因固定高度或溢出裁剪而缺失。公开副露的横牌位置SHALL依据来源家相对副露拥有者确定:下家来源在右侧、对家来源在中间、上家来源在左侧;缺少可靠来源时MUST NOT臆造方向。

#### Scenario: 全知视角显示左右完整手牌
- **WHEN** 用户打开本地全知视角且左右座位各有多行手牌
- **THEN** 左右两家的所有牌面均可见,不会被牌桌区域的固定高度或溢出规则截断

#### Scenario: 副露横牌按来源家定位
- **WHEN** 某家完成吃、碰或明杠且回放帧记录了被吃碰杠牌的来源家
- **THEN** 下家、对家、上家来源分别将横牌放在副露的右、中、左位置

#### Scenario: 副露来源未知
- **WHEN** 旧记录只有副露牌面而没有来源家证据
- **THEN** 副露仍正常显示,但不猜测横牌位置

### Requirement: 时间线内容
时间线SHALL呈现记录中的结构化条目:事件、决策(合法集、所选动作、耗时、回退原因)、动作提交(结果码)、错失吃碰杠(claim_miss)等;线上记录因协议固有的序号跳段导致的信息缺失SHALL被容忍并在时间线上标注,MUST NOT伪造缺失期间的事件。

#### Scenario: 决策条目完整
- **WHEN** 时间线滚动到某决策条目
- **THEN** 显示该决策的合法动作集、所选动作、耗时,若发生回退则显示回退原因

#### Scenario: 跳段标注
- **WHEN** 线上记录存在事件序号跳段
- **THEN** 时间线在跳段处显示缺口标注,重放状态以最近的权威锚点继续

### Requirement: 重放一致性
本地记录的重放SHALL与记录中的动作序列逐动作一致,任何一步出现非法动作SHALL显式报错而非静默纠正;线上记录的重放状态重建SHALL与既有自记日志重放工具(Mirror 语义)同源,MUST NOT引入第二套合法性判定口径。

#### Scenario: 本地重放无非法动作
- **WHEN** 完整回放一条本地对局记录
- **THEN** 每一步动作在当时均为合法动作,无静默替换

#### Scenario: 线上合法集同源
- **WHEN** 线上回放到达某决策点
- **THEN** 重建的合法动作集与该决策点记录的合法集一致

### Requirement: 统一步骤模型
本地批次与线上记录SHALL转换为同一 `ReplaySession`/`ReplayStep` 模型,回放 UI 与导航器MUST NOT按数据来源复制两套实现。一个 `ReplayStep` SHALL以服务端事件 `seqNo` 为线上主序号;本地动作记录没有服务端序号时,SHALL使用带来源标记的派生动作序号。`/state`、动作提交、决策和诊断信息应挂载到已有步骤上,不得因为这些旁路记录额外生成播放步骤。

#### Scenario: 本地与线上共用导航
- **WHEN** 用户分别打开一局本地批次和一局线上记录
- **THEN** 两者均通过同一个上一页、下一页、首尾跳转、序号跳转和时间轴组件改变当前步骤

#### Scenario: 旁路记录不改变步数
- **WHEN** 某个服务端步骤关联多个本地请求或诊断记录
- **THEN** 时间轴仍只有一个步骤,检查器在该步骤内展示这些关联记录

### Requirement: 步骤检查器与状态差异
回放查看器SHALL展示当前步骤的序号来源、事件、关联本地请求和诊断标记;若存在前一步,SHALL展示由前一步到当前步骤的公共状态差异。回放状态只能使用当前步骤及之前的已知信息,不得因最终日志预知后续吃碰杠而提前渲染副露或响应窗口。

#### Scenario: 本地动作步骤检查
- **WHEN** 用户在本地批次回放中选择某个动作步骤
- **THEN** 检查器展示该动作及其派生序号,并可看到当前步骤相对前一步的牌河/手牌/墙变化

#### Scenario: 响应窗口边界
- **WHEN** 用户在弃牌、响应窗口、吃碰杠三个相邻步骤之间前后切换
- **THEN** 每个步骤只显示该步骤已经重建出的响应窗口和副露状态,不得把后续副露提前到前一步
