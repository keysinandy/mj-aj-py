# Spec Delta

## Purpose

定义客户端对三种线上对战模式的控制行为与实时观战数据流:会话启动/停止、参数面、并发对局的房间化呈现,以及不影响对弈的只读观战。

## ADDED Requirements

### Requirement: 锦标赛 Tab 与开赛前轮询
客户端 SHALL 在主导航最前面提供锦标赛 Tab,可配置锦标赛专用令牌和明确选择的策略(policy / BOT / policy-v3 / random),并启动独立的 tournament 会话。令牌 MUST 只从本机平台设置读取,不得进入会话配置、会话列表或日志。会话 SHALL 复用正式赛 runner 的生命周期处理:在赛事开赛前持续轮询赛事状态,在报名/准备阶段执行入席,在赛事运行后持续查找并进入当前令牌有权参与的活跃对局,直到赛事终态或用户停止。

#### Scenario: 配置并启动锦标赛
- **WHEN** 用户在锦标赛 Tab 填入锦标赛令牌并显式选择策略后启动
- **THEN** 令牌保存到本机设置,新建 tournament 会话,会话配置只包含策略参数而不包含令牌

#### Scenario: 开赛前等待
- **WHEN** 锦标赛会话启动且赛事仍在报名/准备阶段
- **THEN** 服务持续轮询赛事状态并显示等待中,不会把会话提前标记为完成

#### Scenario: Key 尚未绑定赛事时继续等待
- **WHEN** 浏览器锦标赛会话的 Key 鉴权成功,但 `/api/me` 暂无 `tournament_id`
- **THEN** 会话每秒重新查询绑定状态并显示等待中;用户停止时中断等待,鉴权失败仍明确报错结束

#### Scenario: 赛事开始后自动入局
- **WHEN** 赛事状态变为 running 且 `/api/me.active_games` 与赛事 `my_games` 有交集
- **THEN** 正式赛 runner 自动启动这些对局的 BotClient worker,并继续轮询后续阶段

#### Scenario: 停止等待中的锦标赛
- **WHEN** 用户在赛事开赛前点击停止
- **THEN** 会话通过 runner 的停止事件中断轮询并以已取消状态结束

### Requirement: 锦标赛运行状态与虚拟日志
锦标赛页面 SHALL 实时展示策略加载状态、目标服务器连通状态、最近检测时间和当前赛事轮询阶段。页面 SHALL 通过可滚动虚拟列表展示策略初始化、连接结果、周期轮询、赛事阶段、普通运行消息和错误；日志 SHALL 按游标增量读取并受服务端缓冲上限约束，完整错误内容可查看。令牌 MUST NOT 写入日志。

#### Scenario: 显示策略与服务器状态
- **WHEN** 用户启动锦标赛或打开已配置的锦标赛页
- **THEN** 页面展示策略尚未启动/加载中/已加载/加载失败，以及服务器检测中/已联通/不可达/鉴权失败和最近检测时间

#### Scenario: 轮询与赛事日志可滚动查看
- **WHEN** 会话持续轮询或产生赛事阶段、入席、对局及错误日志
- **THEN** 日志按时间追加显示，用户可滚动回看并查看选中日志的完整内容，长日志列表只渲染可视区域附近的行

### Requirement: 三模式对弈控制
客户端SHALL支持启动与停止三种线上会话:锦标赛、匹配房(match)、测试房。启动参数SHALL至少包含:策略(policy / BOT / policy-v3)、模型选择、BOT 评价器与回退窗口、policy-v3 置信度阈值、state-rate(默认 16/s)。各模式的对弈语义SHALL与既有命令行 runner 保持一致(复用同一实现,不引入第二套平台协议逻辑);策略默认值SHALL显式呈现,MUST NOT隐式使用 policy(线上首选 BOT)。

#### Scenario: 启动匹配房会话
- **WHEN** 用户配置 BOT(legacy)并启动匹配房会话
- **THEN** 会话以匹配令牌入席,产生对局记录并进入房间列表

#### Scenario: 显式策略默认
- **WHEN** 用户未主动选择策略即启动线上会话
- **THEN** 界面阻止启动并提示显式选择策略(与线上运行手册口径一致)

#### Scenario: 停止会话
- **WHEN** 用户点击停止
- **THEN** 会话按既有 runner 的中断语义安全收尾,对局日志完整落盘

### Requirement: 房间列表
一场线上会话的全部并发对局SHALL以房间列表呈现,每张房间卡片至少显示:对局标识、当前轮次、剩余墙数、状态(进行中/已结束/异常)与最近一次动作摘要;新对局开始与对局结束SHALL动态增删或标记,无须手动刷新。

#### Scenario: 十场并发
- **WHEN** 匹配房会话满房开出 10 场并发对局
- **THEN** 房间列表同时显示 10 张进行中的房间卡片

#### Scenario: 对局结束动态标记
- **WHEN** 某场对局收到终局
- **THEN** 对应卡片转为已结束状态并保留最终积分,列表不闪烁重建

### Requirement: 单局实时观战
点入房间SHALL展示该局实时状态:自家手牌、四家牌河、四家副露、剩余墙数、轮次与积分,以及事件/决策/动作时间线(含合法集、所选动作、决策耗时与回退原因)。观战数据流SHALL从既有对局记录通道只读消费,延迟SHALL控制在秒级;观战订阅MUST NOT改变对弈进程的任何行为与时序。

#### Scenario: 观战状态正确
- **WHEN** 用户点入某进行中的房间
- **THEN** 手牌、牌河、副露、墙数与该局记录文件重建的公共状态一致

#### Scenario: 观战不影响对弈
- **WHEN** 用户反复进入/退出同一房间的观战视图
- **THEN** 该局对弈线程的决策与提交行为不发生变化(记录文件无异常重置或额外请求)

#### Scenario: 时间线实时追加
- **WHEN** 观战期间该局产生新的决策与动作
- **THEN** 时间线在秒级延迟内追加对应条目

### Requirement: 实时观战摸后听口提示
单局实时观战SHALL复用回放查看器的摸后弃牌听口提示：当线上观察座位处于可确认的摸牌 seq 且有合法弃牌时，手牌 hover/focus SHALL显示实际可胡听口及基于本家手牌、四家牌河和副露计算的公开未见数。观战帧MUST NOT包含或读取其他座位暗手身份，且提示计算不得发起额外平台状态请求、动作请求或改变原有对弈时序。

#### Scenario: 线上摸牌 seq 追加提示
- **WHEN** 观战订阅收到观察座位的权威摸牌快照或等价事件帧
- **THEN** 牌桌在该帧的可弃牌上显示听口提示，后续 seq 到达后提示更新为新帧数据

#### Scenario: 观战缺口不沿用旧提示
- **WHEN** 线上事件序号跳段、Mirror 等待全量快照、或当前帧无法确认摸后手牌
- **THEN** 牌桌隐藏听口提示，直到新的权威帧完成分析，不显示上一帧的未见数

#### Scenario: 观战订阅不影响对局
- **WHEN** 用户反复进入、退出或 hover 同一房间的提示
- **THEN** 源 jsonl、平台状态请求、动作提交、决策时序和对局结果与不订阅提示时一致

### Requirement: 会话与记录衔接
线上会话产生的对局SHALL沿用既有结构化日志(按 gid 落盘);会话进行中或结束后,用户SHALL能从房间列表或会话详情直接打开任意对局进入回放查看器。

#### Scenario: 从房间进入回放
- **WHEN** 用户点击某已结束房间的"回放"
- **THEN** 回放查看器加载该 gid 的完整记录并定位到开头
