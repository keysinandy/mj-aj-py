# Design: Optimization Evidence Contract

## Baseline and boundaries

The evidence baseline is `main@e1bcab4`. The loaded kernel, not the Python interpreter name or the source version alone, determines whether an experiment used `rust-weighted-two-ply-v5`. A generation run used for production evidence requires `weighted_kernel_compatible=True` and `degraded=False`; the explicit degraded escape hatch is smoke/parity only. Existing v3-degraded results and v5 results are separate cohorts. The only T0 training-label name is `legacyV2-offline`; online shape-aware `legacyV2` is an inference configuration, not a new teacher identity.

This change is specification-only. The following sections describe future implementation and acceptance criteria, not completed fixes.

## Gate decision model

Gate A consumes the actual offline selection report. A selected eligible checkpoint is sufficient for a first-run eligibility screen, but `promoted=True` without a previous-report comparison is not evidence of inter-generation improvement. If a previous report is declared, use the reported improvement criterion rather than silently omitting the comparison. Gate failures stop later expensive stages.

The fast paired stage is a **rejection screen**, not the full promotion gate. Its output is a per-matrix status (`continue_to_full`, `rejected`, or `insufficient_evidence`) with sample counts, required counts, CI, verdict and reason. Any matrix showing statistically supported regression rejects the candidate. A missing/malformed report or insufficient pairs cannot be reported as a pass. A `non_regression_ambiguous` report can be routed to the independent full gate for confirmation, but neither it nor a mere zero exit code may be presented as promotion. The full paired and runtime release requirements remain unchanged; `superior` from the existing paired scorer must not override `meets_required_pairs=False`.

The pipeline currently writes `offline_report.json` and `fast_paired.json` (a matrix-name-to-report map); the documented full CLI writes `paired_report.json` with a `matrices` map; historical `paired_<matrix>.json` files are flat. The summary reader must normalize these supported shapes into one per-matrix representation, preserve the stage (fast vs full), and never overwrite a full verdict with fast evidence. Missing, rejected, and not-yet-run are distinct states; a rejected gate must remain visibly rejected after early exit. Record provenance required by the existing staged-evaluation-gates specification (commit, model/teacher/dataset/config identities, schedule, seeds and gate metrics) before using the report to promote; a missing identity blocks promotion rather than being inferred from a filename. Reject ambiguous duplicate matrix identities rather than silently choosing one.

Acceptance fixtures must include: offline ineligible; no previous comparison; previous comparison failed; fast regression; fast insufficient pairs; fast ambiguous routed to full but not promoted; full nested report and historical flat report; early-exit summary after rejection. Tests use temporary paths, not committed run artifacts.

## Teacher resume investigation

A completed work item is identified by the persisted `SearchSample.work_id` contract (`source_group`, context/history hashes, teacher seed and *effective* search fingerprint). The generator must compare exactly that identity before relabeling; forced, unsupported and search-evidence paths must obey the same invariant. Resuming with the same source specs/config/loaded kernel must yield the same rows and final dataset fingerprint as uninterrupted generation, regardless of worker count or spec order. A conflicting row is an error, not a silent de-duplication.

One test run reported `remaining=16` versus expected `8`; a later v5 run reported `full=13, first=5, remaining=8`. Root cause is **unconfirmed**. First record the interpreter, actual `kernel_runtime_diagnostic()`, `MJ_KERNELS`, invocation/test order and reproducible seed. On a failure, compare first/full work identities and source trajectories, then compare the generator's pre-search skip key with the returned sample's work ID. If source trajectories differ, investigate stateful ordering/randomness; if only effective search fingerprints differ, align their provenance; only after this distinction choose a code change. No merge-by-key workaround or claim of a repaired bug until the reproduction and fingerprint assertion pass. Generation manifest provenance and shard cohort checks remain mandatory; old and new shards are never mixed.

## Shape Guard and online state

The canonical `legacy-two-ply-frontier-shape-guard` specification at `e1bcab4` defines the current online admission: strict lexicographic improvement of `standing_shape_signature[2:6]` at the first differing class. Seed 290 is a negative admission example and 1787 a positive one; there is no authorization to widen this predicate. The `legacy-v2-shape-aware-two-ply` and `legacy-v2-marginal-structure-guard` pending MODIFIED blocks must be semantically merged with the current canonical requirement before archive: retain that predicate, equality rejection, `admitted_by`, the legacy fallback and standing-shape audit fields, while preserving any speed-band additions. `openspec validate --strict` alone does not detect a textual rollback of a MODIFIED requirement. Resolve remaining archive-header conflicts separately; do not archive a delta that would delete the canonical contract.

`Mirror.build_game()` rebuilds `Game` each decision, while the current X counter is keyed by `Game`. A session-level counter would change online decisions. Before enabling X, establish a mirror-backed per-round identity, round-end/snapshot reset and no cross-game/seat leakage; verify with repeated `build_game()` and actual mirror decision tests. Then require v5-clean paired settlement-score and latency/window-loss evidence against the existing online profile; record the decision in `PROGRESS.md`. The current Y/Z semantics and Piao pass cap are unchanged by this specification. No historical score from a different kernel/configuration is attributed to the proposed X fix.
