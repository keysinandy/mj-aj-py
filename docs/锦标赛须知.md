# 锦标赛须知(网页客户端)

用**浏览器客户端**参加正式锦标赛的最短路径:装环境 → 起网页 → 在网页里填 Key 并启动。

命令行方式见 `docs/锦标赛README.md`;凭据与令牌口径见
`docs/formal-tournament-participation.md`。本文件只管网页这条链路。

## 0. 总览

```
① scripts\setup.ps1 --install --venv   ← 建 .venv 并分层安装依赖
② scripts\web_client.ps1               ← 起 clientd + 前端,自动打开浏览器
③ 浏览器「锦标赛」页 填 Key → 测 Key → 启动并等待赛事
```

三步都做完,剩下的报名、等待开赛、入局全自动。

---

## 1. 环境初始化

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1 --install --venv
```

若当前终端已放开执行策略,等价简写:

```powershell
.\scripts\setup.ps1 --install --venv
```

**它做什么**

`setup.ps1` 是引导层,只负责保证有一个合适的 Python,然后把参数**原样透传**给
`scripts\setup.py`:

1. 按 `py -3.11` → `-3.12` → `-3.13` → `-3.10` → `python3.11` … → `python`
   的顺序探测,取第一个既 ≥ 3.10、又在 Rust 内核支持范围内(≤ 3.13)的解释器;
2. 机器上**只有 3.14 这类超出内核上限的版本**时,不再询问,自动装 Python 3.11
   (Windows 优先 `py install 3.11`,本会话立即可用,不用重开终端);
3. `--venv` 让 setup.py 在仓库根建 `.venv` 并把所有包装进去,**不污染系统 Python**;
4. `--install` 分层安装:核心路径零依赖 → Rust 内核(可选)→ Node(可选)→
   可选组件 → 平台配置模板 → 引擎冒烟测试。

**网页客户端需要的依赖**

网页客户端(clientd)运行依赖 **numpy + websockets**(setup.py 里的 `web` 层),
`--install` 会自动装上。漏装也不会让你看 traceback —— `web_client.ps1` 会先自检
并直接给出修复命令。

**产物与开关**

| 项 | 说明 |
|---|---|
| `.venv\Scripts\python.exe` | 之后的解释器,`web_client.ps1` 会自动优先选它 |
| `MJ_SETUP_NO_AUTO_INSTALL=1` | 关掉全部自动改动(不自动装 Python/Node、不自动重建 `.venv`),只警告 |
| `--skip-tests` | 跳过最后的引擎冒烟测试 |
| `--no-rust` | 明确不构建 Rust 内核(纯 Python 回退,能跑但决策稍慢) |

Rust 内核缺失**不影响上场**,只影响速度:shanten/ukeire 会自动回退纯 Python。

## 2. 启动网页客户端

```powershell
powershell -ExecutionPolicy Bypass -File scripts\web_client.ps1
```

**它做什么**

1. **选解释器** —— 优先仓库 `.venv\Scripts\python.exe`,没有才退回 PATH 上的 `python`;
2. **依赖自检** —— 缺 numpy/websockets 时直接报错并打印 pip 修复命令;
3. **起 clientd** —— sidecar 进程,`HTTP 127.0.0.1:17320` / `WS 127.0.0.1:17321`;
4. **起前端并开浏览器** —— `npm run dev -- --open`;
5. **退出时清理** —— 按 Ctrl+C 会停掉本次启动的 clientd。

**端口**

默认 HTTP **17320** + WS **17321**。被占用时按「偶数 HTTP + 后继 WS」向上找空闲
端口对(范围 17320–17418),选中的端口通过 `VITE_HTTP_BASE` / `VITE_WS_ENDPOINT`
注入前端,无需手工配置。

**首次运行**

`client\node_modules` 缺失时会自动 `npm install`(较慢,需已装 **Node ≥ 22**)。

**日志位置**(出问题先看这两个)

```
local\web-clientd.out.log
local\web-clientd.err.log
```

就绪判据是 `/health` 返回 200,最多等 15s;超时会打印提示并停掉进程。

也可以直接复用 setup 的解释器手工起(排查用):

```powershell
.venv\Scripts\python.exe -m mj.clientd --host 127.0.0.1 --http-port 17320 --ws-port 17321
```

## 3. 在网页中填写锦标赛 Key

浏览器打开后默认落在**「锦标赛」页**(`/` 自动重定向到 `/tournament`)。
顶部导航:锦标赛 / 控制台 / 房间 / 回放 / 设置。

### 3.1 先配服务器地址(「设置」页)

**这一步不能跳过** —— 服务器地址为空时,锦标赛页点启动会直接报
`请先在设置页配置服务器地址`。

进入 **设置**(`/settings`)→「平台连接」卡片:

| 字段 | 填什么 |
|---|---|
| 服务器地址 | 平台地址,例如 `https://10.240.169.190:18080` |
| 锦标赛令牌 | 粘贴**报名令牌** |
| 匹配令牌 / 测试房令牌 | 参赛不需要,留空即可 |

然后:

1. 点 **测试锦标赛连接** —— 该按钮只访问平台身份接口,**不会创建房间或开对局**;
2. 确认返回正常后,点 **保存平台设置**。

> 令牌只写进本机 **gitignored** 的 `local/platform.json`。三种令牌
> (锦标赛 / 匹配 / 测试房)**不能混用**。
>
> ⚠️ 保存会**重写整个文件**:若里面已有顶层 `tournament_token` / `match_token`,
> 会被丢弃。动手前先备份,细节见第 4 节。

### 3.2 在「锦标赛」页填 Key 并启动

切到 **锦标赛**(`/tournament`),「参赛配置」卡片:

1. **锦标赛 Key** —— 粘贴比赛令牌(密码框,即 3.1 里的「锦标赛令牌」,两者是
   同一个值,写的是同一个字段);
2. **参赛策略** —— 下拉选择。线上首选:

   | 策略 | 说明 |
   |---|---|
   | `BOT · legacyV2` | **推荐**。当前加权两步搜索版本,公开未知牌前瞻 + Rust 加速 |
   | `BOT · legacy` | 基础启发式基线,计算轻、行为稳定 |
   | `BOT · shape-v1` | 结合向听/进张/手牌结构评分 |
   | `policy` / `policy-v3` | 需要先在设置页导入并选择 ONNX 模型,否则不允许启动 |
   | `随机策略` | 仅协议/基线用途,**不要用于正式参赛** |

3. 依次点:

   - **保存 Key** → 提示「锦标赛 Key 已安全保存到本机设置」
   - **测试 Key** → 探活 + 鉴权,失败会明确区分「服务器已联通,Key 鉴权失败」
   - **启动并等待赛事** → 真正开跑

**「启动并等待赛事」之后会发生什么**

- 把 Key 落盘到 `local/platform.json`;
- 用 `state_rate=16`、`record=true` 创建 tournament 会话;
- 之后**每秒轮询**,自动完成报名、准备、等待开赛;
- 出现属于本人的对局时自动入局,直到赛事结束或手动停止。

**看什么**

| 卡片 | 内容 |
|---|---|
| 运行状态 | 参赛策略加载情况 / 目标服务器联通与鉴权 / 锦标赛轮询阶段 |
| 锦标赛日志 | 实时滚动日志(错误/提醒/信息),点某行看详情 |
| 锦标赛会话 | 会话列表与状态,运行中可点**停止** |

### 3.3 启动失败对照

| 报错 | 原因 |
|---|---|
| `请先在设置页配置服务器地址` | 3.1 没做,或服务器地址为空 |
| `请填写锦标赛 Key` | Key 为空 |
| `请显式选择锦标赛策略` | 没选策略(无默认值) |
| `请先在设置页导入并选择 ONNX 模型` | 选了 `policy` / `policy-v3` 但没选模型 |
| `令牌尚未绑定锦标赛` (`TOKEN_NOT_BOUND`) | 令牌不是本赛事的报名令牌 |
| `令牌认证失败` (`AUTH_FAILED`) | 令牌错误或已过期 |

## 4. 与命令行方式的关系

两边共用同一个 `local/platform.json`,但**读写的字段形状不同**:

| | 网页客户端(clientd) | 命令行 runner |
|---|---|---|
| 锦标赛令牌 | `tokens.tournament` | 顶层 `tournament_token` 优先,缺失时回退 `tokens.tournament` |
| 自由对战令牌 | `tokens.match` | 顶层 `match_token`(**不读 `tokens.match`**) |

`mj/platform/config.py` 的 `load_tournament_config` 带回退链,所以**网页里填的
锦标赛 Key,命令行 runner 能直接用**(它落在 `tokens.tournament`)。

### ⚠️ 反向不成立,而且保存会覆盖整个文件

clientd 保存设置时,把文件**重写成只有三个键**:

```json
{ "server": "...", "tokens": { "tournament": "", "match": "", "test_room": [] }, "selected_model": "..." }
```

**顶层其他键一律丢失**,包括:

- 顶层 `tournament_token` —— 删掉后命令行回退到 `tokens.tournament`。若你在网页里
  没填 Key,回退拿到的就是空字符串 → 命令行直接不可用;
- 顶层 `match_token` —— **删掉后 `match_runner` 找不到它**(它只认顶层键),
  自由对战命令行会报缺 `match_token`;
- 旧式具名测试房令牌(如 `{"青龙": "...", "白虎": "..."}`)—— 被归一化丢弃。

**动手前先备份 `local/platform.json`**,再决定用哪条链路:用网页就全在网页里配;
要跑命令行自由对战,别让网页覆盖掉顶层 `match_token`。

**同一个令牌不要同时用两条链路参赛**(重复报名/争抢同一席位)。命令行方式的预检、
日志与复盘命令见 `docs/锦标赛README.md`。

## 5. 排障速查

| 现象 | 处理 |
|---|---|
| 浏览器没自动打开 | 看终端打印的 Vite 地址(默认 `http://localhost:5173`,被占则自动 +1) |
| 页面打不开 / 一直转圈 | 确认 clientd 在跑:`Invoke-WebRequest http://127.0.0.1:17320/health` |
| clientd 启动失败 | 读 `local\web-clientd.err.log` |
| 提示缺 numpy/websockets | `& '.venv\Scripts\python.exe' -m pip install numpy websockets` |
| 端口被占用 | 脚本自动换端口对;日志第一行会打印实际使用的 `http=/ws=` |
| `client\node_modules` 装不上 | 先确认 `node -v` ≥ 22;Node 由 nvm 接管时注意 `nvm use` |
| 手改了 `local/platform.json` 但页面没变 | 后端**不缓存**(每次调用都重新读盘),但页面只在打开时读一次设置 → 刷新浏览器页面 |

> 正式赛对局日志是**唯一可复盘数据源**,落在 `local/games/<日期>/<令牌>_<gid>.jsonl`,
> 不要清理。赛后复盘见 `docs/锦标赛README.md` 第 4 节。
