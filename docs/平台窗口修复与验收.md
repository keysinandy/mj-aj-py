# 平台窗口可靠性验收

本页定义平台窗口修复后的发布门。验收只读取 `local/games/` 中的自记日志，
不会连接平台或修改对局记录。

## 1. 离线准入

每次修改平台窗口、状态拉取、镜像或动作提交代码后，先运行：

```bash
python3 -m pytest \
  tests/test_window_acceptance.py \
  tests/test_window_identity_protocol.py \
  tests/test_window_recovery.py \
  tests/test_window_confirmation.py \
  tests/test_claim_miss.py \
  tests/test_state_demand.py \
  tests/test_state_scheduling.py \
  tests/test_state_request_lifecycle.py -q
```

## 2. 冻结版本线上跑批

重启客户端或 runner，确保加载目标 commit。自由对战必须显式选择线上可用的
策略；`shape-v2` 不得用于线上：

```bash
COMMIT=$(git rev-parse HEAD)
python3 -m mj.platform.match_runner --games 10 --strategy bot --state-rate 16
```

正式锦标赛直接使用锦标赛入口完成一轮；不要关闭 recorder。

## 3. 生成并执行发布门

自由对战日志文件名包含 room id；正式锦标赛日志文件名包含 tournament id，
两种命名均受支持：

```bash
python3 scripts/window_acceptance.py <room-or-tournament-id> \
  --scope fresh_acceptance \
  --commit "$COMMIT" \
  --gate \
  --out local/acceptance/<room-or-tournament-id>_report.json
```

退出码：

- `0`：重放合法性通过，且可靠性门通过；
- `1`：重放或合法集对账失败；
- `2`：可靠性门失败；
- argparse 的参数/日志发现错误沿用其标准非零退出码。

旧行为保持兼容：不传 `--gate` 时，退出码只判断重放与合法集，不代表窗口
可靠性验收通过。

## 4. 默认发布门

`--gate` 默认要求以下指标全部为 0：

- `chosen_null_server_timeout`：服务端吃/碰超时时策略尚未完成决策；
- `confirmation_retry_exhausted`；
- `identity_confirmation_budget_exhausted`；
- `action_rejected`；
- `action_uncertain`；
- `mirror_drift`；
- `window_409`；
- `duplicate_post_after_409`；
- `duplicate_post_after_uncertain`；
- `canonical_client_loss`；
- `hard_fail_total`。

此外必须同时满足：

- `--scope fresh_acceptance`；
- `--commit` 非空，记录本轮冻结代码版本。

如已人工确认少量窗口 409 为对手抢先认领，可显式放宽：

```bash
--max-window-409 N
```

如镜像漂移已逐条确认且被权威快照正确恢复，可显式放宽：

```bash
--max-mirror-drift N
```

不得为让报告变绿而放宽其他核心指标。

## 5. 失败归因

门失败后，先从报告的 `reliability.gate.violations` 获取失败指标，再逐局检查：

```bash
python3 -m mj.logview <gid> --windows
python3 -m mj.log_replay <gid>
```

关键口径：

- `chosen=null + server_timeout_*` 表示策略尚未被调用，属于观测、确认或调度链损失；
- `chosen=-1` 表示策略主动过，不计机会损失；
- `chosen` 为非 pass 动作表示策略已选择，但动作没有成功落地；
- `claim_miss` 是诊断记录，不应脱离同一 `window_attempt_key` 的确认、决策、
  POST 与终止记录单独解释；
- `partial_identity` 在服务端未提供窗口身份字段时可作为证据完备度说明，但不能
  掩盖实际的 `canonical_client_loss`。

可选的网关/服务端时序证据通过重复的 `--transport-log <jsonl>` 参数合入报告。
