## 目标与基线

在十场共享 15/s 的条件下，缩短 peng 临界确认排队，准确区分确认恢复与最终
窗口损失，并建立可复用的房间验收报告。保持 SSE + 增量 state 和现有策略。

本次起点为 `6ffb110`，工作区干净。基线房 `a_e84af19cf87e`：使用
`policy / runs/bc0/best.pt`，10/10 收官，879/879 动作成功，chi 76 次成功，
response_409=0，post_uncertain=0；state 10285 次，底层 429 重试 5 次。
排队 p50/p95/max 为 215.2/466.0/753.7ms；urgent 为 44.4/63.5/180.7ms。

重新核验基线发现：两条 `decision_boundary_resync` 都在同一窗口恢复后成功
peng（b0 seq=533、b2 seq=1433），不是两个最终漏碰。对应确认请求丢失 deadline，
按普通请求排队 456.8ms、296.4ms。先前将它们直接称为机会损失的结论更正。
基线 replay 的 illegal=0 不代表完整结算验证：round_ended 覆盖不足，工具
显示 n_rounds=0，不能据此宣称全部 80 手已逐手结算对账。

## 实施范围

1. peng 临界确认（子 Agent A：bot_client.py 和对应窗口测试）。
   - 把提交前的“需要确认”从动作结果未知/409 重锚中区分出来。
   - 仍由每场串行主循环执行一次 seq=0，保留窗口身份及调度 deadline。
   - 秒级弃牌 ts 的 T+1 仅是最早关闭提示；用于调度的乐观上界最迟
     T+2，不得冒充可提交截止，不得给已明确关闭的窗续期。
   - 最新快照 phase、本人 responding_seats、精确 deadline、窗口身份及
     最新合法集共同决定后续动作；已关闭/变更窗口不得复用旧动作。
   - 正常 peng 确认记单独诊断；只在最终失去原窗口且仍有原合法候选时记录
     miss。已成功恢复不再提前写 claim_miss。未知 POST 和 409 仍不重发。
   - 测试覆盖：确认仍开放成功、已关闭、换弃牌/换局、截止失效、自己不在
     responding_seats、策略 pass、成功回声和 409/未知结果防重。

2. 请求诊断（子 Agent B：api.py、recorder.py 和诊断测试；主 Agent 整合调用）。
   - 每次物理 state 尝试记录开始时刻/结果/429 等摘要，供解释重试与排队。
   - req 增加兼容的 request_kind（WINDOW_PENG、WINDOW_CHI、RESYNC、
     SSE_DELTA），它是诊断用途，本轮不改 throttle 排序接口。
   - Bot 汇总显式累计 state 物理尝试/429 重试，并确保不被动作 TLS 信息污染。
   - 保留每次物理 retry 重新 acquire 和动作 POST 单次提交语义。

3. 验收分析（主 Agent：脚本、计划/验收记录）。
   - 输出动作/确认/最终 miss、429、各请求类型排队分位和收官统计。
   - 基线旧日志允许 request_kind 未知；避免将 unknown 强猜成新类型。
   - 按实际覆盖报告 snapshot/事件/决策 replay，列明缺失结算证据。

不在本轮实施：策略/权重调整、16/s、sleep 调参、release-aware EDF、完整
StateDemand 重写。当前 burst 实际发许可后总设 next=now+interval，不能
凭构造参数断言它导致了 429；先收集物理请求证据，不做无效 burst 对照。

5. 后续线上调度验收优先使用启发式 BOT：
   `python3 -m mj.platform.match_runner --games 10 --strategy bot --state-rate 15`，
   整房自然收官，不自动开启额外实验。`policy` 仅用于明确的模型对照，并记录
   对应 `--ckpt`。
6. 报告对比：10/10 收官；动作提交、response_409、post_uncertain、窗口最终
   miss；peng 确认恢复数/排队/关闭数；chi 决策与提交；state 429；按类型 queue
   p50/p95/max。urgent p95 150ms 为观察目标，不作为协议保证。

上线结果按真实数据判定；无 claim_miss 不能单独证明无漏窗，安全重锚也不
自动算失败。随机牌局和网络不同，一房对比只作为效果观察，不作因果保证。

  "现在"起算一个间隔，不把网络耗时叠进冷却（旧实现会多等一个间隔）；
  `feedback_cooldown_ms` 按 `新 _next − 基线` 统计，只计反馈自身施加
