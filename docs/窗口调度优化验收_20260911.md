## 结论与后续

第二轮达到本轮安全验收目标：无动作 409、无未知 POST、无可观测
`claim_miss`，窗口确认 14/14 open；429 降至 5，urgent 队列 p95 65.8ms。
不过两轮牌局/网络/负载不同，不能单独作 429 下降的因果证明；普通队列
p50 反而上升。暂不提高到 16/s，也不引入 release-aware EDF。

下一步优先保留源弃牌序号作为跨 seq=0 的稳定窗口身份，并补 HTTP 分阶段
耗时/服务端时间与 `Retry-After` 诊断；积累多房样本后再决定是否调整冷却量。

验收边界：`auto_played=0`、`409=0` 或 `claim_miss=0` 都不能单独证明没有
未观测窗口；必须结合快照覆盖、合法集回放、服务端 timeout 和实际动作记录。
